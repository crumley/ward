# Glossary

> **Layer:** intent · foundation (global). A reference index — read out of order. **Status:**
> living.

A quick reference for Ward's vocabulary. The **defining slice** owns each term; that slice is
authoritative and this table only points to it (it never holds a second definition).

| Term                             | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                      | Defining slice                                                                                                                                 |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Workspace**                    | The local, personal, self-sufficient root in which a human and their agents work. Holds all metadata, tooling, and skills.                                                                                                                                                                                                                                                                                                   | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Project**                      | A coherent body of work with its own definition of success; heavyweight or ad hoc.                                                                                                                                                                                                                                                                                                                                           | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Floor**                        | A project in the room-numbering metaphor: addressed by a **floor number** (`1`, `2`, `3`…); its rooms carry the floor number plus a room code, e.g. `4A12` (floor 4, room A12). Floor numbers are **monotonic** — a closed floor's number is retired, never reused.                                                                                                                                                          | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Task**                         | One unit of trackable, deliverable work; started, paused, resumed, closed. May span repos/worktrees; local-only or remote-linked; heavyweight or ad hoc.                                                                                                                                                                                                                                                                     | [domain-model](../01-concepts/00-domain-model.md), [work-lifecycle](../01-concepts/03-work-lifecycle.md)                                       |
| **Anchor**                       | The task-owned scratch medium a room occupies — a **worktree** (code) or a **workdir** (non-code deep work). At most one occupant at a time (a room, or an elided session acting directly); an occupied anchor is written only through its occupant.                                                                                                                                                                         | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Worktree**                     | An anchor kind: a branch of one repository, checked out to be changed independently of its main line. Carries a **disposition**, fixed at creation: `deliverable` (destined for the main line) or `sandbox` (never opens a PR; exempt from delivery toil; base pinned).                                                                                                                                                      | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Workdir**                      | An anchor kind: a task-owned working directory for deep work that changes no repository (research, analysis, data wrangling). Holds the scratch; its governed record is artifacts with provenance, not commits.                                                                                                                                                                                                              | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Room**                         | The innermost scope, where deep hands-on work happens. A reusable resource that hosts sessions and occupies exactly one anchor; occupancy is derived from its sessions, and a freed room's code is reused.                                                                                                                                                                                                                   | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Repository**                   | A project repo the workspace knows and keeps a current main checkout of.                                                                                                                                                                                                                                                                                                                                                     | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Main line**                    | A repository's default branch; the canonical checkout tracks it, refreshed on a cadence. Work never merges to it except via PR (or explicit human permission).                                                                                                                                                                                                                                                               | [work-lifecycle](../01-concepts/03-work-lifecycle.md)                                                                                          |
| **Refresh**                      | Pulling the workspace's canonical main checkouts from origin on a cadence, so new worktrees branch from current code.                                                                                                                                                                                                                                                                                                        | [work-lifecycle](../01-concepts/03-work-lifecycle.md)                                                                                          |
| **Rebase**                       | Rebasing an existing worktree onto the refreshed main line, so work in progress stays current and merge surprises shrink.                                                                                                                                                                                                                                                                                                    | [work-lifecycle](../01-concepts/03-work-lifecycle.md)                                                                                          |
| **Scope**                        | The level in the hierarchy an agent is responsible for (project / task / room) — _what_ it attends to. One of a session's two axes, alongside working directory.                                                                                                                                                                                                                                                             | [domain-model](../01-concepts/00-domain-model.md), [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                             |
| **Working directory**            | Where a session stands and loads context from — _where_ it operates; chosen independently of scope (root for broad scopes, a repo/worktree dir for narrow ones).                                                                                                                                                                                                                                                             | [domain-model](../01-concepts/00-domain-model.md), [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                             |
| **Agent**                        | A running AI instance doing work within one scope and working directory.                                                                                                                                                                                                                                                                                                                                                     | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Persona**                      | A named role definition (a **name** plus a **role**) that shapes an agent's behavior; tailored to a scope; open/configurable set. Name and role are internal and must not leak.                                                                                                                                                                                                                                              | [domain-model](../01-concepts/00-domain-model.md), [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                             |
| **House supervisor**             | Status/routing persona at **workspace** scope; knows where every project stands and routes between them; owns no project outcome (the human owns workspace direction); favors a fast model. "Supervisor" for short.                                                                                                                                                                                                          | [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                                                                                |
| **Attending**                    | Teacher persona at project scope; owns the project outcome; gives final approval.                                                                                                                                                                                                                                                                                                                                            | [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                                                                                |
| **Charge nurse**                 | Teacher persona that tracks status across a project's work and routes/dispatches; never descends into detail; favors a fast model.                                                                                                                                                                                                                                                                                           | [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                                                                                |
| **Resident**                     | Teacher persona at task scope; owns the task outcome; briefs and directs rooms and evaluates them rather than doing the work.                                                                                                                                                                                                                                                                                                | [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                                                                                |
| **Medical student**              | Learner persona doing hands-on work inside a room.                                                                                                                                                                                                                                                                                                                                                                           | [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                                                                                |
| **Teaching loop**                | Seniors teach, juniors learn, and learning flows back up — feeding reflection and the system learning about itself.                                                                                                                                                                                                                                                                                                          | [scopes-and-personas](../01-concepts/01-scopes-and-personas.md), [reflection](../01-concepts/04-reflection-and-evolution.md)                   |
| **Session**                      | One bounded episode of an agent working at a scope; opened, running, closed, resumed, woken; recorded with a **harness handle** for recovery and reflection. Has exactly one identity.                                                                                                                                                                                                                                       | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md)                                                                          |
| **Open vs. running**             | _Open_ = a live thread, started and not closed, regardless of any attached process. _Running_ = an active process attached on this machine right now — a **derived live overlay**, never stored; stored session state is only _open_ or _closed_.                                                                                                                                                                            | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md)                                                                          |
| **Status (derived)**             | Each leaf records its own state; a containing scope's status is **derived** from its children, never stored as a separate field. Non-derivable judgments (priority, blocked-reason) are recorded where they apply.                                                                                                                                                                                                           | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Open / Close / Resume / Wake** | The session lifecycle operations; resume is idempotent and turns open into running by re-attaching the live run (the stored state stays open); closed stays closed.                                                                                                                                                                                                                                                          | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md)                                                                          |
| **Context loading**              | How a session acquires its context — a harness-neutral `AGENTS.md` hierarchy keyed to the working directory, built deterministically and append-biased for token-cache sharing.                                                                                                                                                                                                                                              | [context-loading](../01-concepts/05-context-loading.md)                                                                                        |
| **Harness**                      | The agent runtime behind a session; stores its own session history; pluggable and selectable per scope.                                                                                                                                                                                                                                                                                                                      | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md), [agent-harness](../02-subsystems/03-agent-harness.md)                   |
| **Harness handle**               | A session's stored locator for its underlying harness run (harness type + native run id) — a recorded _attribute_, not an identity; used to resume the run and locate it for reflection. Analogous to a task's remote-work-item link.                                                                                                                                                                                        | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md)                                                                          |
| **Dispatch**                     | Handing work or context _downward_ to something within a scope.                                                                                                                                                                                                                                                                                                                                                              | [domain-model](../01-concepts/00-domain-model.md), [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                             |
| **Report**                       | Sending status _upward_ to the containing scope.                                                                                                                                                                                                                                                                                                                                                                             | [domain-model](../01-concepts/00-domain-model.md), [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                             |
| **Wake / nudge**                 | Notifying a scope when a condition is met, so it can detach instead of blocking. Two flavors: a **milestone** wake fires on a matching report from the target (re-armable per cycle); a **completion** wake fires when the target scope completes.                                                                                                                                                                           | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md), [messaging-coordination](../02-subsystems/02-messaging-coordination.md) |
| **Recovery rounds**              | The judgment pass that ends cold-start recovery: top-down, the status personas take stock of their own spans — the supervisor over projects, each charge nurse over its project — deciding what the mechanical re-arm cannot and reporting upward, so the returning human is told where everything stands.                                                                                                                   | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md)                                                                          |
| **Recovery record**              | The durable episode a recovery writes about itself: when it ran, per-thread outcomes (re-attached / failed with cause / skipped as closed), wakes re-armed and fired, and the rounds' conclusions — what a recovery reflection reads.                                                                                                                                                                                        | [sessions-and-lifecycle](../01-concepts/02-sessions-and-lifecycle.md)                                                                          |
| **Fork (side quest)**            | A bounded detour that inherits a scope's context, resolves a sub-problem (possibly at a different scope/persona), and returns a clean result — protecting the origin's context. Inherits by **exact-clone** (harness-dependent) or **distilled brief** (harness-neutral baseline).                                                                                                                                           | [domain-model](../01-concepts/00-domain-model.md), [scopes-and-personas](../01-concepts/01-scopes-and-personas.md)                             |
| **Artifact**                     | _Any_ durable output meant to be shared across sessions/agents (briefs, decisions, datasets, scripts, …). Carries provenance; discoverable across its scope; owned by its origin.                                                                                                                                                                                                                                            | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Provenance (lineage)**         | The recorded who/persona, working directory, session, why, and source-artifacts behind an artifact — so it can be traced and trusted later.                                                                                                                                                                                                                                                                                  | [domain-model](../01-concepts/00-domain-model.md), [principles §11](01-principles.md)                                                          |
| **Brief**                        | An artifact type: a handoff document that conjures and orients another agent (what, where, why, what's expected).                                                                                                                                                                                                                                                                                                            | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Identity (slug + code)**       | A human-memorable name: a meaningful slug plus a short code, easy to say and type. Not always globally unique — prefer memorable codes sized to real cardinality (a project's code is a floor number; a room's is floor number + room code, e.g. `4A12`), with time and context as further ambiguity-breakers. Open **sessions** and open **tasks** take bare, workspace-unique codes. Identity need not mirror containment. | [domain-model](../01-concepts/00-domain-model.md)                                                                                              |
| **Local↔remote boundary**        | The privacy boundary between the personal workspace and shared remote artifacts; local/personal/internal context (incl. persona names) must not leak outward.                                                                                                                                                                                                                                                                | [principles §4](01-principles.md), [work-lifecycle](../01-concepts/03-work-lifecycle.md)                                                       |
| **Lifecycle hooks**              | Customizable, **idempotent** setup/teardown actions for transitions (e.g. worktree dependency init, applying a theme); validated as done-or-not on resume and no-op if satisfied.                                                                                                                                                                                                                                            | [work-lifecycle](../01-concepts/03-work-lifecycle.md)                                                                                          |
| **Workflow policy**              | Ward's opinionated, workspace-encoded, evolvable rules for committing and merging (e.g. never-merge-to-main); reconciled on upgrade.                                                                                                                                                                                                                                                                                         | [work-lifecycle](../01-concepts/03-work-lifecycle.md)                                                                                          |
| **Gated action**                 | An outward-facing or irreversible action (merge/push to main, create/comment on a remote item, delete unmerged work) that requires the human or explicitly delegated authority; local + reversible actions are autonomous.                                                                                                                                                                                                   | [principles §18](01-principles.md)                                                                                                             |
| **Reflection**                   | A _family_ of goal-directed routines that turn experience and the teaching loop into better skills, tooling, personas, and Ward improvements; runs on a cadence and at scope boundaries; chunked and rolled up to scale.                                                                                                                                                                                                     | [reflection](../01-concepts/04-reflection-and-evolution.md)                                                                                    |
| **Scope-boundary reflection**    | Reflection triggered when a scope closes (project/task), focused on that scope's arc for focused, actionable improvements.                                                                                                                                                                                                                                                                                                   | [reflection](../01-concepts/04-reflection-and-evolution.md)                                                                                    |
| **Reflection cursor**            | The per-(scope, reflection-goal) marker recording how far a reflection has already processed, so the next run handles only what is new.                                                                                                                                                                                                                                                                                      | [reflection](../01-concepts/04-reflection-and-evolution.md)                                                                                    |
| **Update vs. migrate**           | _Update_ brings artifacts in line with the current CLI; _migrate_ transforms structure/schema forward. You can update without migrating.                                                                                                                                                                                                                                                                                     | [reflection](../01-concepts/04-reflection-and-evolution.md)                                                                                    |
| **Reconciliation**               | The agent-guided process for folding new Ward defaults into a workspace that has diverged from them.                                                                                                                                                                                                                                                                                                                         | [work-lifecycle](../01-concepts/03-work-lifecycle.md), [reflection](../01-concepts/04-reflection-and-evolution.md)                             |
| **Seam**                         | A boundary along which the implementation may vary; stated as a **contract** in intent, with its build planned in `design/`.                                                                                                                                                                                                                                                                                                 | [subsystems](../02-subsystems/)                                                                                                                |
| **Intent vs. design**            | **Intent** is the durable _what & why_ (this tree); **design** is the _how_ — the implementation plans that realize it ([`../../design/`](../../design/)). The dividing heuristic: _if we changed how we build it, would this sentence still hold?_                                                                                                                                                                          | [`../README.md`](../README.md)                                                                                                                 |
